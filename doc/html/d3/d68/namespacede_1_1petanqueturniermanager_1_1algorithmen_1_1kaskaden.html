Jedes Feld entsteht durch eine Folge von Sieger- und Verlierer-Entscheidungen im Kaskadenbaum. Der pfad kodiert diesen Entstehungsweg (z. B. "SV" = Sieger in Runde 1, Verlierer in Runde 2). Der bezeichner ist der alphabetische Name des Feldes (A, B, C, …), der sich aus der lexikografischen Position des Pfades ergibt.

record de.petanqueturniermanager.algorithmen.kaskaden.KaskadenKoGruppenRunde ( String pfad,
int anzTeams,
List< KaskadenKoSpielPaar > spielPaare,
int anzFreilose )



Jede Gruppe entsteht aus einer Folge von Sieger-/Verlierer-Entscheidungen vorangegangener Kaskadenrunden (kodiert im pfad). In der ersten Kaskadenrunde gibt es genau eine Gruppe mit leerem Pfad (alle Teams).

Freilos-Konvention: Bei ungerader anzTeams erhält das Team an letzter Position (Position anzTeams) ein Freilos. Es erscheint nicht in spielPaare, sondern wird durch die Größenberechnung in die Verlierer-Gruppe übernommen.

Invariante: anzTeams == 2 * spielPaare.size() + anzFreilose

Parameter
pfadS/V-Pfad der Gruppe (leer für Startrunde, z. B. "S", "VS")
anzTeamsAnzahl Teams in dieser Gruppe (≥ 1)
spielPaarefloor(anzTeams / 2) Spielpaarungen, positionen 1-basiert
anzFreiloseAnzahl Teams mit Freilos (0 oder 1); Freilos-Team → Verlierer-Seite

◆ KaskadenKoSpielPaar()

record de.petanqueturniermanager.algorithmen.kaskaden.KaskadenKoSpielPaar ( int spielNr,
int positionA,
int positionB,
Integer zielPositionSieger,
Integer zielPositionVerlierer )



Die Positionen beziehen sich auf die 1-basierte Reihenfolge innerhalb der jeweiligen Gruppe. In Runde 1 entsprechen sie direkt den Setzpositionen (SP) der Teams; in späteren Runden sind es die relativen Positionen innerhalb der entstandenen Sieger- oder Verlierer-Gruppen.

Freilos-Konvention: Das Freilos-Team (bei ungerader Teamanzahl immer die letzte Position in der Gruppe) erscheint nicht in den spielPaare einer KaskadenKoGruppenRunde. Es wird durch die Größenberechnung implizit in die Verlierer-Gruppe übernommen.

Zielposition-Hinweis: zielPositionSieger und zielPositionVerlierer beschreiben, in welche Slot-Nummer des Folge-Feldes der Sieger bzw. Verlierer dieses Spiels gelangt. Sie sind zunächst null (noch nicht befüllt) und können von der aufrufenden Schicht ergänzt werden, sobald die Mapping-Logik implementiert ist.

Parameter
spielNrlaufende Nummer innerhalb der Gruppe (1-basiert)
positionAerste Teamposition in der Gruppe (1-basiert)
positionBzweite Teamposition in der Gruppe (1-basiert)
zielPositionSiegerZiel-Slot im nächsten Sieger-Feld; null wenn noch nicht befüllt
zielPositionVerliererZiel-Slot im nächsten Verlierer-Feld; null wenn noch nicht befüllt
